# VolvoxAI runtime (`libvolvoxai.so`)

**One shared library.** This Rust crate builds a single cdylib, `libvolvoxai.so`,
that exposes the C inference engine (`../native`) as a
[Synurang](https://github.com/ivere27/synurang) service defined in
[`../proto/volvoxai.proto`](../proto/volvoxai.proto). It follows the volvoxgrid
pattern but, because volvoxai's engine is C, Rust is only thin FFI glue:

- `src/gen/volvoxai_ffi_plugin.rs` — generated by the Synurang **Rust** generator
  (`lang=rust,mode=plugin_server`): the `VolvoxAIServicePlugin` trait, the FFI
  dispatcher, and the `#[no_mangle] Synurang_*` entry points (unary + streaming).
- `src/lib.rs` — implements that trait by calling the engine over `extern "C"`;
  registers the plugin on load via `ctor`. No inference logic lives here.
- `build.rs` — `prost_build` compiles the proto into message types, and `cc`
  compiles **all of `../native/*.c`** (minus `main.c`) straight into this cdylib.

The result is one `.so` that serves **FFI** (loaded in-process) and **TCP** with
the same code — the transport is chosen by the caller. Streaming `Generate` works
(the Rust generator emits a real `PluginStreamSender`).

## Build

```bash
make build_codegen_tool     # one-time: cargo install protoc-gen-synurang-ffi-rs from GitHub
make build_server           # proto_rust (generate+inject) then cargo build --release
# -> runtime/target/release/libvolvoxai.so
```

Needs a Rust toolchain, `protoc`, and `libvulkan-dev` (for `native/vulkan_engine.c`,
same as the Docker image). Clients generate their own bindings from the same
proto in their language (`lang=dart`, `lang=go`, …) and load this `.so` or dial
it over TCP.

## Reality check

The engine is a **global singleton** (`native/engine.c`), so the runtime
serializes every call behind one mutex and keeps **one model loaded at a time**;
`model_id` is a validation token over that single context. True multi-model /
concurrent inference needs per-context state in the engine.

| RPC | Status |
| --- | --- |
| `Ping`, `LoadModel` (paths), `UnloadModel`, `GetModelInfo`, `ListModels` | implemented |
| `Run`, `GetTensor` | implemented (F32 tensors) |
| `Generate` | streaming greedy decode via tokenizer + prefill/decode; sampling + VLM image TODO |
| `Classify` | pre-decoded NHWC tensor + top-k; encoded-image decode TODO |
| `GetCapabilities` | CPU only — TODO: emit the `docs/operation_list.md` matrix |
| `Detect`, `RecognizeCTC` | TODO: port post-processing from `native/main.c` |
| `LoadModel` inline bytes, `ModelInfo` inputs/outputs + `op_counts` | TODO (needs engine graph introspection) |
