# 9C장 — CUDA 백엔드 내부 (NVIDIA GPU에 직접 말 걸기)

*자신에게 맞는 배지를 읽으세요: 🌱 **아이디어**(누구나, 코드 없이) · 🔧 **만들기**(코드 조금) · 🔬
**심화**(엔진 개발자). 처음이신가요? 🌱 부분만 따라가세요 — 그것만으로 CUDA 이야기 전체가 이어집니다.*

*목표: VolvoxAI의 **CUDA 백엔드** — 같은 그래프를 **NVIDIA 그래픽 카드** 위에서 도는 옵트인 경로 —
를 이해합니다. 그것도 NVIDIA의 큰 소프트웨어 키트를 하나도 번들하지 않고 말이지요. 이 장은
[9장](09-native-engine-architecture.md)의 동반 장입니다: 그 장이 네이티브 엔진과 여러 백엔드를
세웠다면, 이 장은 그중 CUDA 하나를 앞에서 뒤까지 끝까지 확대합니다.*

> 🌱 **핵심 아이디어.** 9장은 기기에 무슨 칩이 있든 찾아 쓰는 하나의 작은 프로그램을 보여줬습니다.
> 그 칩 중 하나가 **NVIDIA GPU** — 게이머와 AI 연구소가 쓰는 카드로, 수천 명의 작은 일꾼이 나란히
> 계산을 하는 칩 — 입니다. 그 카드에 평범하게 말을 걸려면 보통 수 기가바이트의 NVIDIA 소프트웨어를
> 깔아야 합니다. VolvoxAI는 대신 특이한 선택을 합니다: 카드에 줄 **자기만의** 수학 프로그램을 직접
> 가져오고, 이미 기기에 있는 작은 조각인 **드라이버**(프로그램과 카드 사이의 번역기)만 빌립니다. 그래서
> 같은 하나의 프로그램이, 큰 카드가 있으면 그것을 켜고, 없으면 평범한 노트북에서도 그대로 돕니다. 이
> 장은 그 방식의 전체 여정입니다: 카드에 어떻게 말을 거는지, 숫자를 어떻게 카드 *위에* 두는지, 어떻게
> 카드 위에서 **학습** 까지 하는지 — 그리고 그 내내 어떻게 조심스럽고 정직한지.

🔧 여기의 모든 것은 `native/src/backends/cuda/` 와 진입 파일 `cuda_engine.c`, `cuda_engine.h`,
`cuda_kernels.cu`, `cuda_training_kernels.cu` 에 있습니다. CUDA는 **기본으로 꺼져** 있습니다; 빌드
시점에 켜고 실행 시점에 선택합니다. 정식의 간결한 사양은 [`docs/cuda.md`](../../cuda.md) 이며 — 이 장은
같은 내용을 친절하고 완전하게 걷는 안내입니다.

🔬 머릿속에 담아둘 한 줄 설명: **"직접 CUDA Driver API + VolvoxAI 소유의 PTX 커널."** cuBLAS도, cuDNN도,
cuTENSOR도, NCCL도, CUDA Runtime(`cudart`)도 없습니다. 엔진은 그래프 실행기, 메모리 레지던시, 모든 커널,
손실, 옵티마이저, 양자화기를 *소유* 하고, NVIDIA로부터 딱 하나 — 안정적인 **Driver API** — 만 실행
시점에 빌립니다.

## 9C.1 GPU란 실제로 무엇인가 (그리고 "CUDA"의 뜻)

> 🌱 **아이디어.** 보통의 프로세서(**CPU**)는 아주 영리한 요리사 몇 명과 같습니다: 각자 복잡한 일을 할
> 수 있지만, 수가 몇 안 됩니다. **GPU** 는 라인쿡으로 가득 찬 경기장과 같습니다: 한 명 한 명은 간단한
> 단계만 하지만, *수천 명* 이 동시에 일합니다. 신경망은 대부분 같은 간단한 단계 — *두 수를 곱하고
> 더하기* — 를 어마어마하게 많이 반복하므로, 경기장 가득한 라인쿡이 요리사 몇 명보다 훨씬 빨리
> 끝냅니다. **CUDA** 는 그 경기장에 할 일 목록을 건네는 NVIDIA 시스템의 이름일 뿐입니다. 그리고
> **커널** 은 쿡들을 위해 쓴 하나의 작업입니다: "모든 쿡, 자기 숫자를 하나 집어 두 배로." 커널을 한 번
> 띄우면 수천 명의 쿡이 각자 다른 데이터 조각에 대해 동시에 그것을 실행합니다.

🔧 구체적으로: CUDA **커널** 은 **스레드** 하나당 한 번 도는 작은 함수입니다; 스레드는 **블록** 으로
묶이고, 블록은 **그리드** 를 이룹니다. VolvoxAI가 커널을 띄울 때 그리드와 블록 크기를 정하면, GPU는 그
함수를 `그리드 × 블록` 개만큼, 각자 자기 인덱스를 갖고 돌립니다. 전형적인 "스레드 하나당 원소 하나" 런치는
이렇게 생겼습니다(엔진의 런치 헬퍼):

```c
// cuda/host/cuda_graph_memory_host.inc
static int cuda_launch_1d(CUfunction function, uint32_t elements, void** args) {
    const unsigned int block = 256;                       // 블록당 쿡 256명
    unsigned int grid = elements / block + (elements % block != 0u);
    return cuda_launch(function, grid, 1, 1, block, 1, 1, 0, args);
}
```

🔬 디바이스 커널은 **독립형(freestanding)** 입니다: CUDA 헤더를 하나도 포함하지 않고 NVIDIA 라이브러리
루틴을 하나도 부르지 않습니다. 반올림을 정확히 통제하려고 몇몇 수학 기본 연산을 인라인 PTX 어셈블리로
직접 적어두기까지 합니다 — 예를 들어 지수에 `ex2.approx.f32`, 따로 반올림하는 곱에 `mul.rn.f32`
(`cuda_kernels.cu`). 그 독립형 규율 덕분에 *같은* `.cu` 소스를 NVIDIA의 `nvcc` **또는** Clang의 NVPTX
백엔드가, SDK 없이도 컴파일할 수 있습니다.

## 9C.2 독립형 요령: 드라이버는 빌리고, 커널은 직접 가져온다

> 🌱 **아이디어.** NVIDIA 카드를 쓰려면 대부분의 프로그램은 NVIDIA의 거대한 도구상자를 깔고 빌드 시점에
> 붙여 넣습니다. 그러면 그 프로그램은 도구상자를 *영원히* 필요로 하고, 도구상자가 있는 곳에서만 돕니다.
> VolvoxAI는 그 거래를 거부합니다. 기기에는 NVIDIA가 이미 깔아둔 작은, 늘 있는 조각이 하나 있습니다:
> **드라이버** — 프로그램과 카드 사이의 번역기. VolvoxAI는 *실행하는 바로 그 순간* 그 드라이버에게
> 다가가 어깨를 툭 치고 필요한 몇 가지 기본 서비스만 부탁합니다: "카드에 메모리 좀 만들어 줘," "이 숫자들
> 복사해 줘," "이 작업 돌려 줘." 실제 수학은 전부 자기가 가져옵니다. 결과: **하나의 프로그램 파일** 이,
> 카드가 있으면 GPU 발전소가 되고 없으면 조용한 CPU 프로그램이 됩니다 — 재설치도, 별도 빌드도 없이.

🔧 "실행 시점에 드라이버에게 부탁하기"는 문자 그대로 `dlopen` + `dlsym` 입니다 — 9장이 Vulkan과 OpenGL에
대해 보여준 것과 같은 실행 시점 로딩 동작입니다(`cuda/host/cuda_driver_host.inc`):

```c
const char* names[] = {"libcuda.so.1", "libcuda.so"};   // 툴킷이 아니라 NVIDIA 드라이버
for (i = 0; i < 2; i++) { cuda_library = dlopen(names[i], RTLD_NOW | RTLD_LOCAL); if (cuda_library) break; }
// 그런 다음 각 진입점을 이름으로 찾습니다:
p_cuInit            = dlsym(cuda_library, "cuInit");
p_cuMemAlloc        = dlsym(cuda_library, "cuMemAlloc_v2");
p_cuLaunchKernel    = dlsym(cuda_library, "cuLaunchKernel");
p_cuMemcpyHtoD      = dlsym(cuda_library, "cuMemcpyHtoD_v2");
// ... Driver API 함수의 짧고 고정된 목록
```

🔬 찾아 쓰는 함수 목록은 일부러 아주 작고 안정적입니다: init/디바이스 질의, **기본 컨텍스트**, **스트림**
하나, 모듈 로드/언로드, get-function, 할당/해제, 동기 복사 둘, 런치 하나, 에러 이름 조회. 몇 가지는
**선택적** 입니다 — CUDA **그래프** 캡처 함수(§9C.7), 그리고 풀 프로파일에서 **이벤트 타이밍**
함수(§9C.14) — 드라이버가 너무 오래되어 이들을 제공하지 못해도 백엔드는 잘 돕니다. 절대 건드리지 않는 것:
`cudart`, cuBLAS/cuBLASLt, cuDNN, cuTENSOR, NCCL, 또는 다른 ML 런타임. 빌드가 그것을 증명합니다 —
`-lcuda*` 링크 플래그가 없고, 관련 플래그는 `-ldl` 뿐입니다.

## 9C.3 PTX: 수학을 한 번 쓰고, 드라이버가 갓 굽게 한다

> 🌱 **아이디어.** 카드는 엔진의 C 코드를 직접 읽지 못합니다. 그래서 VolvoxAI는 각 수학 작업을 한 번
> 쓰고, 빌드 단계가 그것을 **PTX** 로 바꿉니다 — GPU 자신의 손글씨로 적은 레시피라고 생각하세요. 그
> 레시피는 프로그램 파일 *안에* 넣어둡니다. 프로그램이 시작해서 진짜 카드를 찾으면, 레시피를 드라이버에
> 건네고, **드라이버가 그것을 구워** 바로 그 카드가 이해하는 정확한 명령으로 만듭니다. 레시피 하나로,
> 모든 NVIDIA 카드가 자기만의 완벽한 버전을 굽습니다 — 그래서 VolvoxAI는 카드마다 다른 프로그램이
> 필요 없습니다.

🔧 파이프라인은 9장의 "한 소스, 여러 대상" 규율을 NVIDIA용으로 옮긴 것입니다:

```
cuda_kernels.cu ───nvcc 또는 clang(NVPTX)──▶ 순방향 PTX ──┐
cuda_training_kernels.cu ────────────────────▶ 학습 PTX ──┤  바이트로 임베드 (tools/embed_cuda_ptx.py)
                                                          ▼
                                        native/volvoxai 와 native/volvoxai-full 안에
                                                          │  실행 시점에:
                                          cuModuleLoadDataEx(...)  ← 드라이버가 이 카드용으로 PTX를 JIT 컴파일
```

생성된 PTX는 **절대 커밋하거나 손으로 편집하지 않습니다**; `tools/embed_cuda_ptx.py` 가 임베드하는
결정적 빌드 산출물입니다. 각 `.cu` 파일은 `cuda/kernels/*.inc` 의 많은 작은 커널 조각을 `#include` 하는
**컴포지션 루트** 라서, 커널이 여러 모듈로 흩어지지 않고 주제별로 정리됩니다.

🔬 PTX 모듈은 일부러 **둘** 입니다(§9C.4 참고): 순방향 모듈과 학습/PTQ 모듈. 빌드는 부동소수점 정책 둘 —
**엄격(strict)**(`--fmad=false` / `-ffp-contract=off`)과 **빠름(fast)**(`--fmad=true` /
`-ffp-contract=fast`) — 을 `-DVOLVOXAI_CUDA_FAST_FP32` 로 고릅니다(§9C.8). 대상 연산 능력은
`-DVOLVOXAI_CUDA_ARCH`(기본 75)로 넘기지만, 드라이버의 JIT 단계 덕에 하나의 PTX가 여러 카드에 걸쳐 돕니다.
소스 컴포지션 테스트(`tools/tests/test_cuda_source_composition.py`)가 인클루드 그래프가 완전하고
비순환인지, 디바이스 조각이 호스트 코드로 손을 뻗지 않는지, 순방향 모듈이 학습 커널에 의존하지 않는지를
검사합니다.

## 9C.4 배낭 두 개: 추론 프로파일과 풀 프로파일

> 🌱 **아이디어.** VolvoxAI는 GPU 프로그램을 두 크기로 냅니다. **작은 배낭**("추론")은 이미 완성된
> 모델을 *돌리기* 만 합니다 — 폰, 카메라, 출시된 앱에 딱 맞지요. **큰 배낭**("풀")은 모델을 *학습* 하고
> *줄이기* 도 해서 도구를 더 넣습니다. 작은 쪽은 학습 도구를 말 그대로 담고 있지 않습니다 — 숨기거나 끈
> 게 아니라, 아예 안 챙긴 겁니다. 덕분에 출시 프로그램이 가볍고, 학습 기계가 있으면 안 될 곳에서 실수로
> 돌 수 없습니다.

🔧 두 배낭은 두 빌드 타깃입니다:

```bash
cmake --build build/cuda --target volvoxai volvoxai-full
```

- `volvoxai`(추론): CUDA 순방향 백엔드 + 순방향 PTX 모듈만.
- `volvoxai-full`(풀): full 전용 불투명 `VxTrainer` API와 그 비공개 학습 상태, 옵티마이저,
  프로파일러, W8 저작, 그리고 학습/PTX 모듈을 더함.

🔬 이 분리는 `#ifdef` 흩뿌리기가 아니라 **번역 단위(translation-unit) 경계** 입니다. 추론 프로파일에는
컴파일된 학습 구현이 없고, 공개 학습 심볼이 없고, 학습 PTX는 아예 임베드되지 않습니다.
`#if VOLVOXAI_ENABLE_TRAINING` 이 추가 호스트 조각을 가두고, 심볼 경계 테스트가 추론 빌드를 깨끗하게
유지합니다. 그래서 "학습기를 담고 있기나 한가?"에 실행 플래그가 아니라 단단하고 검증 가능한 답이 있습니다.

## 9C.5 엄격한 라우팅: GPU에서 하거나, 못 했다고 분명히 말하거나

> 🌱 **아이디어.** GPU를 요청하면, VolvoxAI는 약속합니다: 당신의 모델을 GPU에서 돌리거나, **못 했다고
> 알려주거나** — 느린 CPU에서 조용히 끝내 놓고 GPU가 한 척 믿게 하지는 절대 않습니다. 왜 이리 엄격할까요?
> 조용한 전환은 문제를 숨기기 때문입니다: 모델이 "GPU에서 된다"처럼 보이면서 몰래 기어가지요. 컴파일
> 정책은 CUDA가 선호인지 필수인지, 연산 폴백을 허용하는지를 명시합니다. 컴파일은 그 정책을 만족하는
> 검증된 경로를 만들거나, 만들지 못한 이유를 보고합니다.

🔧 `vx_model_compile`에 넘기는 `VxBackendPolicy`의 `backend`를 `"cuda"`로 설정하면 CUDA를 선택합니다.
엄격한 CUDA 경로는 `mode = VX_BACKEND_REQUIRE`,
`operator_fallback = VX_OPERATOR_FALLBACK_FORBID`로 요청합니다. 지원하지 않는 작업은 컴파일 단계에서
실패하며, `vx_execution_context_execute`가 CPU에서 그래프를 다시 시도하지 않습니다.

🔬 CUDA 제공자는 전체 경로를 검증하고 컴파일된 모델 보고서에 제공자, 디바이스, 경로 증거를 기록합니다.
풀 프로파일 학습도 내부에서 같은 전부-아니면-전무 규칙을 따릅니다. CUDA 상태를 바꾸기 전에 전체 역방향
계획을 프리플라이트하고, 한 번 걸린 CUDA 실패 뒤에는 남은 명령을 실행하지 않습니다.

## 9C.6 숫자를 GPU 책상에 그대로 두기 (레지던시)

> 🌱 **아이디어.** 카드에는 자기 메모리 — 자기 **책상** — 이 있습니다. GPU를 쓸 때 느린 부분은 종종
> 계산이 아니라 컴퓨터 책상과 카드 책상 사이로 *종이를 나르는 일* 입니다. 그래서 VolvoxAI는 단계 사이에
> **숫자를 카드 책상에 두려고** 애씁니다. 모델의 가중치는 한 번 옮겨 거기 둡니다. 계산의 중간 결과도
> 거기 두고, 컴퓨터 쪽에서 실제로 읽어야 할 때만 가져옵니다. 이를 해내려고 엔진은 작은 공책을 둡니다:
> 카드 위 숫자 더미마다, 그것이 컴퓨터의 어느 더미와 맞는지, 그리고 가장 신선한 사본이 카드에 있는지
> 컴퓨터에 있는지를 적어둡니다.

🔧 호출자는 디바이스 메모리를 절대 보지 않습니다. `vx_execution_context_set_input`은 입력 바이트를
런타임 소유 저장소에 복사하고, `vx_result_read`는 불변 결과 스냅샷을 호출자에게 복사합니다. CUDA 제공자
안에서는 비공개 **슬롯 테이블**이 런타임 소유 텐서 저장소를 디바이스 할당에 매핑합니다. 아래 타입별
진입점은 구현 세부 사항입니다:

```c
int cuda_graph_matmul_f32(const float* input, const float* weight, const float* bias,
                          float* output, int rows, int d_in, int d_out);
void cuda_graph_mark_host(const void* host, size_t bytes, int is_weight); // "CPU가 이걸 바꿨다"
int  cuda_graph_sync_host(const void* host, size_t bytes, int is_weight); // "CPU가 이걸 읽어야 한다"
```

🔬 레지던시 계층(`cuda/host/cuda_graph_memory_host.inc`)은 엔진에서 가장 안전이 중요한 코드입니다:

- **런타임 소유 저장소가 내부 슬롯을 식별합니다.** 최대 **8,192** 개의 추가 전용(append-only) 슬롯을
  **16,384-항목** 개방 주소 해시로 찾고, 예비로 정확 선형 스캔이 있으며, *포함-슬롯* 조회로 내부 뷰(행,
  슬라이스)가 부모 할당 + 바이트 오프셋으로 풀립니다.
- **슬롯당 더티 비트 둘**(`host_dirty`, `device_dirty`)이 신선한 사본이 어디 있는지 추적해, 업로드와
  다운로드가 정말 필요할 때만 일어납니다. 가중치는 한 번 올라가 상주하고, 옵티마이저가 갱신한 가중치와
  Adam 모멘트는 무언가가 명시적으로 읽거나 저장할 때까지 단계에 걸쳐 디바이스 권위로 남습니다.
- **주소 재사용이 위험이고, 처리되어 있습니다.** C 쪽이 임시 텐서를 해제하면 그 주소는 나중에 *다른*
  텐서에 재활용될 수 있습니다. 실패할 수 있는 드라이버 호출 전에, 엔진은 죽은 임시 정체성을
  **격리(quarantine)** 하고(저장소 포인터를 벗기고 디바이스 버퍼는 나중에 풀 익명 고아로 유지),
  **슬롯 에포크** 카운터를 올려, 재활용된 주소가 죽은 텐서의 남은 디바이스 데이터를 실수로 읽는 일이
  절대 없게 합니다. 진짜 모델 가중치는 이 모든 과정 내내 상주로 유지됩니다
  (`cuda_graph_release_transients`).

전송은 평범한 동기 `cuMemcpyHtoD_v2` / `cuMemcpyDtoH_v2` 를 씁니다; 아직 핀 메모리 할당자나 비동기
파이프라인은 일부러 두지 않았고, 이는 모델을 단순하게 유지합니다(§9C.16).

## 9C.7 춤을 한 번 녹화해 다시 튼다 (CUDA 그래프 리플레이)

> 🌱 **아이디어.** 카드에 작업을 한 번에 하나씩 건네는 데는 매번 약간의 부대비용이 있습니다 — 춤 동작을
> 하나하나 불러주는 것처럼요. *같은 루틴* 이 여러 번 반복될 참이면(추론처럼 — 매 입력이 똑같은 단계
> 목록을 돕니다), VolvoxAI는 **춤 전체를 한 번 녹화** 하고 카드에게 "녹화한 루틴 다시" 라고 말할 수
> 있습니다 — 오가는 대화가 훨씬 줄지요. 조심스럽게 합니다: 단순하고 얌전한 루틴만 녹화하고, 먼저 한 번
> 완전히 돌려보며 놀랄 일이 없는지 확인하고, 모델이나 그 메모리에 대해 *무엇이든* 바뀌면 녹화를 버리고
> 다시 배웁니다. 녹화는 언제나 속도 향상일 뿐, 답을 바꿀 수 없습니다.

🔧 이것이 NVIDIA의 **CUDA 그래프** 캡처-리플레이를, 조심스러운 상태 기계로 감싼 것입니다
(`cuda/host/cuda_graph_lifecycle_host.inc`). 각 순방향은 몇 패스 중 하나로 돕니다:

```
OBSERVE   → 평범히 돌리되, 정확한 런치 목록과 "쓰기 전 읽기(read-before-write)" 입력을 기록
CAPTURE   → 같은 목록을 CUDA 그래프로 리플레이, 인스턴스화, 런치
VALIDATE  → 빠른 경로: 이미 만든 그래프를 그냥 다시 런치
(INELIGIBLE → 평범한 런치, 언제나 옳음)
```

🔬 허용 목록은 일부러 보수적입니다 — Linear/Gemm/MatMul, PReLU/Sigmoid, Conv2D/Add,
Concat/MaxPool2D/ResizeNearest2D/Reshape, 그리고 물리 양자화 연산들. 리플레이를 불안전하게 만들 만한 것은
계획을 **무효화** 합니다: 모델 세대 변경, 슬롯 에포크 변경(메모리 이동), 디버그/프리픽스/행 실행,
SDK 백엔드나 어댑터 효과, 학습, 이벤트 프로파일링, 또는 캡처/런치/동기 실패. 결정적으로, 드라이버가
스트림을 캡처하지 못하면 엔진은 **커널을 하나도 붙들기 전에 물러나** 그 순방향은 끝까지 돕니다.
리플레이는 속도를 위해 정확성을 절대 맞바꾸지 않습니다.

## 9C.8 조심스러운 산술: FP32 약속

> 🌱 **아이디어.** 컴퓨터는 계산을 *어떻게* 하느냐에 따라 숫자를 조금씩 다르게 반올림할 수 있고, 그 작은
> 차이가 쌓일 수 있습니다. VolvoxAI는 GPU의 답을 믿을 수 있고 반복 가능하게 하고 싶어, 기본적으로 카드에게
> 곱셈과 덧셈을 **따로따로, 조심히 반올림하는 단계** 로 하라고 말합니다 — CPU가 하는 방식 그대로 —
> 한 번만 반올림하는 더 빠른 합친 단계 대신에요. 원한다면 더 빠른 모드를 켤 수 있습니다(생 속도가 필요하고
> 낮은 자릿수가 조금 달라도 괜찮다면). 어느 쪽이든, "대충 빠른 수학" 지름길은 절대 켜지 않고, 특수한
> 저정밀 텐서 하드웨어도 절대 쓰지 않습니다; 정직한 32비트 산술입니다.

🔧 빌드 스위치 하나로 정책을 고릅니다:

| 정책 | CMake 옵션 | 컴파일러 동작 |
|---|---|---|
| 엄격 F32 (기본) | `VOLVOXAI_CUDA_FAST_FP32=OFF` | `nvcc --fmad=false` 또는 Clang `-ffp-contract=off` |
| 빠른 F32 | `VOLVOXAI_CUDA_FAST_FP32=ON` | `nvcc --fmad=true` 또는 Clang `-ffp-contract=fast` |

🔬 엄격 F32는 해당되는 곱/덧셈 쌍을 따로 반올림해(융합 곱-덧셈 없음) 유지하며, 이것이 정확성 테스트가
허용 오차를 재는 기준인 no-FMA PTX 계약을 정의합니다. 모든 그래프에 대해 CPU/GPU 비트 동일 출력을 약속하지는
**않습니다** — 병렬 리덕션 순서는 여전히 다릅니다 — *반올림 규칙* 을 약속합니다. 두 정책 다 **TF32** 나
텐서 코어를 켜지 않습니다; 커널은 텐서 코어 명령을 절대 내지 않습니다. 몇몇 지점은 플래그와 무관하게 손으로
반올림을 고정하고(인라인 `mul.rn`/`add.rn`), 소프트맥스는 일부러 마스킹된 `-무한대` 로짓을 `exp(-80)` 이
아니라 정확한 0으로 만들어 CPU 참조와 맞춥니다.

## 9C.9 순방향으로 무엇을 돌릴 수 있나 (F32 추론)

> 🌱 **아이디어.** "순방향" 은 그저 완성된 모델을 *돌려* 답을 얻는 것입니다(1장). GPU 백엔드는 앞서 만난
> 큰 메뉴의 구성 요소들에 대해 이를 할 줄 압니다 — 숫자를 곱하고 결합하는 층들, 모양을 잡는 "활성화"
> 단계들, 정규화기들, 풀링과 리사이즈 단계들, 모델이 앞선 단어를 되돌아보게 하는 어텐션, 그리고 히트맵을
> 상자로 바꾸는 비전 후처리. 모델이 메뉴에 있는 블록만으로 지어졌다면, 전체가 카드에서 돕니다.

🔧 F32 디스패처가 다루는 것(from `docs/cuda.md`, 그리고 `cuda_engine.h` 의 `cuda_graph_*_f32` 진입점):

- **덴스 & 어댑터:** Linear, MatMul, Gemm, 라우팅된 LoRA 오버레이.
- **컨볼루션:** Conv1D, Conv2D, ConvTranspose2D.
- **원소별 & 활성화:** Add/Mul/Sub/Div/Where/Mask; ReLU, Sigmoid, GELU, SiLU, Tanh, HardSwish,
  HardSigmoid, LeakyReLU, PReLU, Clip.
- **정규화 & 리듀스:** LayerNorm, RMSNorm, GroupNorm, BatchNorm2D, 마지막 축 Softmax/LogSoftmax,
  ReduceSum/ReduceMean.
- **풀 & 리사이즈, 이동 & 형상:** 풀링, 최근접/이중선형 리사이즈, Embedding, Transpose, Expand,
  축-0 Gather, Pad, Slice, Split, Concat, 복사류 형상.
- **어텐션 & MoE & 비전:** 팩드-QKV SDPA, 쿼리 범위 SDPA, CrossSDPA, 융합 CrossAttention;
  MoERouter, MoELinear; SpatialSoftargmaxY, ProfileX/Y, MeanHeight, NonMaxSuppression.

🔬 런타임은 흔한 꼬리 몇 개도 융합합니다 — Add+ReLU/ReLU6, Add3+ReLU/ReLU6, 그리고 해당되는
Conv2D+잔차-Add — 그래서 융합 패턴이 런치 하나가 됩니다. 몇몇 연산은 일부러 CUDA F32에 없습니다(ArgMax,
RoPE, SSM/SelectiveScan, Sin, Cos); 그것이 필요한 모델은 그 노드를 다른 데로
라우팅하거나 순수 CUDA 실행의 범위 밖입니다.

## 9C.10 작은 정수 모델 돌리기 (W8A8 추론)

> 🌱 **아이디어.** 6장은 모델의 숫자를 32비트 소수 대신 작은 8비트 정수로 저장해 모델을 줄였습니다 — 4배
> 작고, 정수 계산은 쌉니다. GPU 백엔드는 그 줄인 모델을 **정수로** 돌릴 수 있습니다 — 몰래 다시 소수로
> 부풀리지 않고요. 각 층이 필요로 하는 작은 "스케일" 표를 지니고 카드 위에서 정수 산술을 바로 합니다.

🔧 물리 I8/U8 실행이 다루는 것: QLinear/QMatMul/QGemm/QEmbedding/QConv2D/QAdd, QSiLU/QGELU(캐시된
256바이트 룩업 테이블 포함), QGroupNorm/QLayerNorm, QSDPA와 쿼리 범위 QSDPA, QArgMax/QMaskedMean,
타입별 Quantize/Dequantize/Requantize, 바이트 복사와 형상 별칭, 그리고 같은 도메인의 최근접
Resize/MaxPool2D/Concat. 진입점은 `cuda_engine.h` 의 `cuda_graph_q*_i8u8(...)` 함수들입니다.

🔬 바이트 복사, 풀링, 리사이즈, 컨캣은 **호환되는 dtype, 스케일, 제로포인트** 를 요구합니다 — 백엔드는
한 양자화 도메인을 다른 것으로 몰래 재해석하지 않습니다. 이것은 F32 경로와 별개의 진짜 정수 추론이며,
위의 같은 레지던시와 (허용 목록 연산에 대해) 리플레이 기계를 재사용합니다.

## 9C.11 GPU에서 학습하기 (네이티브 학습)

> 🌱 **아이디어.** 큰 배낭은 모델을 *돌리는* 것 이상을 할 수 있습니다 — 카드 위에서 바로 모델을
> **가르칠** 수 있습니다. 가르치기(4–5장)란: 모델을 순방향으로 돌리고, 얼마나 틀렸는지 재고, 그 오류를
> **거꾸로** 밀어 각 가중치가 어떻게 바뀌어야 하는지 찾고, 가중치를 슬쩍 미는 것. 이 모두를 카드에서
> 하면 숫자가 카드 책상에 머물러(빠름) 학습 데이터가 당신 기기에 머뭅니다(사적). 그리고 트랜잭션적입니다 —
> 조심스러운 전부-아니면-전무: 어떤 배치가 망가진 숫자를 내면, 그 배치는 모델을 반쯤 갱신하는 대신
> 깔끔히 버려집니다.

🔧 `native/volvoxai-full` 학습 단계는 전부 디바이스에서 돕니다:

1. 전체 역방향 명령 계획을 세우고 **프리플라이트**(커널이 하나라도 없으면 일찍 거부);
2. F32 순방향 그래프를 돌림;
3. 가중 교차 엔트로피 손실 기울기를 디바이스에서 씨앗 뿌림;
4. 모든 역방향 명령을 실행해 기울기 대상에 더함;
5. 학습 가능 기울기에 비유한(non-finite) 값이 있는지 검사;
6. 유한한 각 마이크로배치를 **트랜잭션적으로** 누적;
7. 하나의 전역 기울기 노름과 클립 스케일을 계산;
8. **SGD** 또는 **AdamW** 를 적용.

불투명한 `CudaTrainingWindow`(`cuda_engine.h` 에 선언)가 마이크로배치에 걸쳐 누적 기울기와 작은 스칼라
리덕션을 소유합니다.

🔬 볼 만한 설계 포인트 몇 가지:

- **역방향 메뉴가 순방향 메뉴를 반영합니다** — Linear/MatMul/Gemm 기울기, 브로드캐스트 Add/Mul(융합
  활성화 게이트 포함), 모든 활성화 기울기, 마지막 축 리덕션/소프트맥스, Embedding/Dropout/형상 연산,
  LayerNorm/RMSNorm/GroupNorm/BatchNorm2D, 언그룹드와 뎁스와이즈 Conv2D, 풀링/리사이즈/전치/컨캣/분할,
  SDPA와 CrossSDPA, 그리고 MoE.
- **역방향은 이름으로 디스패치됩니다.** 공유 플래너가 WGSL식 명령(`matMulBackward`/`input_main`,
  `conv2DBackward`/`weight_main`, …)으로 말하면, 번역 계층
  (`cuda/host/cuda_training_scheduler_host.inc` 의 `cuda_training_command()`)이 각각을 CUDA 커널로
  매핑합니다. 이름이 매핑되지 않으면 프리플라이트가 전체 계획을 사양합니다 — 일부만 돌리는 일이 절대
  없습니다.
- **거부된 마이크로배치는 아무것도 바꾸지 않습니다.** 누적 버퍼는 마이크로배치에 걸쳐 지속됩니다;
  비유한 배치는 누적 윈도를 건드리지 않고 버려집니다. 옵티마이저 적용 실패는 윈도를 버립니다(임의의
  디바이스 실패는 트랜잭션 롤백을 주지 않으니), 이것이 정직한 선택입니다.
- **SDPA/CrossSDPA 학습** 은 소프트맥스 확률과 점수 기울기를 위한 전용 디바이스 워크스페이스를 쓰며,
  트랜잭션적으로 키우고 정리 시 해제하며, 엄격 빌드가 반복 가능하도록 고정된 64-레인 리덕션을 씁니다.

## 9C.12 GPU에서 모델 줄이기 (W8 저작 / PTQ)

> 🌱 **아이디어.** 7장은 학습된 모델을 그 작은 정수 버전으로 바꿨습니다. 큰 배낭은 그 줄이기를 **카드
> 위에서** 도 할 수 있습니다. 영리하고 조심스러운 부분: 모든 검사가 통과하기 전에는 진짜 출력을 절대
> 건드리지 않습니다. 먼저 연습장에서 작업하고 — 각 행의 스케일을 구하고, 나쁜 숫자가 없는지 검사하고,
> 바이어스가 맞는지 검사하고 — *그 모두* 가 깨끗할 때에만 완성된 정수 가중치를 씁니다. 그래서 나쁜 입력이
> 반쯤 줄어 망가진 모델을 남길 수 없습니다.

🔧 풀 프로파일의 비공개 구현은 다음 내부 진입점으로 정식 행-우선 W8을 저작합니다:

```c
int cuda_training_quantize_w8_f32(const float* source, int8_t* output, float* scales,
        int32_t* zero_points, uint32_t rows, uint32_t columns,
        uint32_t transpose_source, uint32_t scheme, uint32_t scale_policy,
        const float* bias, float input_scale, int32_t* packed_bias,
        uint64_t* saturation_count, uint32_t* out_status);
```

스킴 0은 대칭 좁은 I8(제로포인트 0, `scale = max(|row|)/127`); 스킴 1은 비대칭 전체 I8. `transpose_source`
는 호스트 전치 없이 `IN_OUT` 마스터를 읽고; 선택적 F32 바이어스는 입력·가중치 스케일로 I32에 패킹됩니다.

🔬 커널(`cuda/kernels/cuda_quantize_w8_kernels.inc`)은 **트랜잭션 파이프라인** 을 구현합니다:
`reset → reduce → 스크래치 파라미터 유도 → 바이어스 검증 → 파라미터 커밋 → quantize → 포화 합산 →
바이어스 패킹`. 목적지 배열(스케일, 제로포인트, 바이트, I32 바이어스, 포화 총계)은 공유 상태 워드가 여전히
0인 *뒤에야* 이후 단계가 씁니다. 상태 워드는 실패 부류마다 비트 플래그를 갖습니다(잘못된 인수 / 비유한
소스 / 나쁜 파라미터 / 나쁜 바이어스). 반올림은 f64 `cvt.rni` 로 CPU 양자화기와 비트 단위로 맞춥니다.
저작된 텐서는 CPU 재패킹 없이 §9C.10의 W8A8 커널로 들어갑니다.

## 9C.13 풀 프로파일의 소유권

> 🌱 **아이디어.** 학습에는 임시 활성화, 기울기, 옵티마이저 상태, 역방향 계획이 필요합니다. 풀 명령이
> 학습 단계 동안 이들을 모두 소유하며, 추론 애플리케이션에는 그 상태를 바꾸는 핸들이 노출되지 않습니다.

🔧 CUDA 역방향 계획, 저장 값, 기울기 버퍼, 옵티마이저 상태는 `native/volvoxai-full`에 비공개입니다.
기본 `volvoxai.h` 헤더는 추론 전용이며 불투명한
`VxRuntime → VxModel → VxCompiledModel → VxExecutionContext → VxResult` 생명주기로 구성됩니다.
full 전용 `volvoxai_full.h` 헤더는 불투명한 `VxTrainer`를 추가하지만 변경 가능한 그래프나 옵티마이저
저장소는 노출하지 않습니다.

🔬 Driver 로더, 물리 디바이스, 기본 컨텍스트, PTX 모듈, 함수 캐시, 단일 스트림은 뮤텍스로 보호되고
참조 카운트되는 `CudaDeviceState`에 있습니다. 각 `VxEngineState`는 텐서 상주 상태, 리플레이,
활성화 LUT, 작업 공간, 옵티마이저 미러, 프로파일러 기록, 카운터를 위한 별도의 CUDA 캡슐을
소유합니다. 공유 스트림의 작업은 직렬화되며, 변경 가능한 그래프 또는 학습 상태는 컨텍스트 사이에
공유되지 않습니다.

🔬 JavaScript 학습은 유지되는 `Trainer` 객체를 사용합니다. 단계 결과는 복사된 기울기와 안정적인
`updatedTensorNames`를 내놓고, 체크포인트 내보내기는 단계가 끝난 뒤 별도 연산으로 수행합니다.
네이티브 학습은 이에 대응하는 비공개 스텝과 명시적 commit/rollback의 `VxTrainer` 생명주기를
사용합니다.

## 9C.14 커널용 스톱워치 (이벤트 프로파일러)

> 🌱 **아이디어.** 카드에서 *어떤* 단계가 느린지 알고 싶다면, 큰 배낭에 내장 스톱워치가 있습니다. 설정
> 하나로 켜고 모델을 돌리면, 각 종류의 작업이 얼마나 걸렸는지 작은 스프레드시트를 씁니다. 카드 자체의
> 작업 시간만 재고 — 숫자를 오가며 나르는 시간은 아니고 — 그러니 읽을 때 그 점을 염두에 둬야 합니다.

🔧 첫 CUDA init 전에 환경 변수 하나를 설정합니다:

```bash
VOLVOXAI_CUDA_PROFILE_PATH=/path/trainstep-kernels.csv \
  native/volvoxai-full train models/my_model --cuda ...
```

CSV는 스코프, PTX 진입점, 정확한 런치 시그니처로 집계합니다:
`record,scope,complete,entry,grid_*,block_*,shared_bytes,count,total_ms,mean_ms,max_ms`.

🔬 CUDA-이벤트 타이밍은 디바이스 커널 구간만 잽니다 — 전송, 호스트 계획, 할당, API 부대비용, 동기
대기는 제외 — 그러니 전송 포함 벽시계 시간은 따로 재야 합니다. 프로파일러를 켜면 프로파일된 순방향의
CUDA 그래프 캡처/리플레이가 **비활성화** 되어 각 런치가 개별로 보입니다; `complete=1` 스코프 행이 완전한
네이티브 풀 명령 학습 프로파일의 권위 있는 표시입니다. 프로파일러가 꺼지면 이 코드는 하나도 돌지 않고, 추론
프로파일에는 아예 없습니다.

---

## 9C.15 더 빠르게: 전술과 융합

> 🌱 **아이디어.** 모든 작업에는 평범하고 언제나 옳은 방법이 있고 — 자주 나타나는 형상에는 — 특별히
> 다듬은 더 빠른 방법이 있습니다. VolvoxAI는 둘 다 둡니다: 평범한 버전은 어떤 형상에도 옳은 답을
> 보장하고, 손으로 고른 "전술" 이 흔한 경우를 빠르게 합니다. 또 이웃한 단계를 붙여("융합") 카드가 둘
> 대신 하나의 합친 작업을 하게 합니다.

🔧 추론 전술: 언그룹드 1×1 Conv2D 타일, 특화된 뎁스와이즈 3×3/5×5, Conv2D/QConv2D ReLU6 접기,
Add3와 Conv2D+잔차-Add 융합, 형상/컨캣-후-역양자화 별칭, 텐서-슬롯 해싱, 그리고 §9C.7의 보수적 그래프
리플레이. 학습 전술: 공유 메모리 16×16 덴스 순방향/dInput/dWeight 타일, 결정적 64-레인 리덕션, 스테이징된
64-레인 어텐션 행, 그리고 채널-폭 선택이 있는 언그룹드 HWIO 3×3 Conv2D 타일.

🔬 정직하게 알아둘 절충: **일반(비전술)** 커널은 속도보다 단순하고 패리티에 맞는 형상을 선호해서, 여럿이
원소마다 행 통계를 다시 계산하니 특징 폭에 대해 이차적일 수 있습니다. 이들은 정확성의 바닥이고, 전술이
흔한 형상의 빠른 경로입니다. 자동 튜닝은 없습니다; 전술 선택은 호스트 쪽 휴리스틱이고, 어떤 전술에도
맞지 않는 형상은 일반 커널로 떨어집니다.

## 9C.16 하지 않는 것 (정직한 한계)

> 🌱 **아이디어.** 좋은 설명서는 도구가 *못 하는* 것을 말해, 놀랄 일이 없게 합니다. CUDA 백엔드는
> 만능이 아니라 집중형입니다.

🔬 현재 한계(from `docs/cuda.md`):

- **네이티브 FP16/BF16 수학 없음** — 16비트 패키지 가중치는 넓혀 F32로 계산.
- **TF32나 텐서 코어 없음; cuBLAS/cuDNN/NCCL 없음; CUDA Runtime 없음.**
- **CUDA에서 양자화 역방향과 QAT 없음; 멀티-GPU 없음.**
- **Conv 학습** 은 groups = 1 또는 뎁스와이즈(= 입력 채널)를 지원; 컨볼루션 에필로그는
  none/ReLU/ReLU6; 융합 잔차-Add 경로는 해당되는 1×1 conv로 제한.
- **어텐션** 은 head dim ≤ 64 필요(융합 CrossAttention은 폭 ≤ 64도; QSDPA는 head dim이 4로 나뉘고
  ≤ 64). 소프트맥스/리덕션은 마지막 축; F32 Gather는 축 0; Pad/Slice는 랭크 ≤ 4.
- 런치 크기와 원소 개수는 **32비트** 커널 파라미터로 제한.
- **공개 호출자 소유 디바이스 버퍼 API 없음**, 핀 호스트 스테이징 없음, 비동기 전송 파이프라인 없음;
  풀 명령 학습이 임시 활성화와 기울기를 비공개로 소유함.

이들은 버그가 아니라 — 일부러 작고 감사 가능한 백엔드의 그어진 경계입니다.

## 9C.17 옳다는 걸 어떻게 아나 (검증)

> 🌱 **아이디어.** 이 중 아무것도 믿음으로 신뢰하지 않습니다. GPU 백엔드를 빌드하고 각 조각이 옳은 답을
> 내는지 검사하는 테스트 더미가 있습니다 — 돌리기, 줄이기, 배우기, 심지어 출시용 작은 배낭이 정말 학습
> 도구를 하나도 담지 않았는지까지. 진짜 NVIDIA 카드가 있으면, 실패한 테스트는 어깨 으쓱이 아니라 진짜
> 결함으로 취급됩니다.

🔧 집중 스위트는 CUDA 커널, 런타임 라우팅, 학습, PTQ, 프로파일 경계 테스트를 빌드·실행하고,
소스 컴포지션·엄격/빠름 빌드 계약·결정적 PTX 임베딩에 대한 순수 파이썬 검사를 더합니다:

```bash
python3 -B -m unittest \
  tools.tests.test_cuda_source_composition \
  tools.tests.test_cuda_fp32_contract \
  tools.tests.test_embed_cuda_ptx
```

🔬 CUDA 테스트는 Driver API나 쓸 만한 디바이스가 없을 때에 **한해서만** CTest 스킵 코드 77을 씁니다;
디바이스가 발견되면 어떤 PTX 로드, JIT, 모듈 해석, 검증, 실행 오류도 테스트 실패이지 스킵이 아닙니다.
CPU/JS 참조 대비 정확성은 `tests/parity/` 아래 패리티 하니스의 일이며, 그것은 따로 다룰 주제입니다
(참고: [`docs/testing.md`](../../testing.md)).

## 9C.18 한 장의 그림으로 본 CUDA 백엔드

> 🌱 **아이디어 요약.** 브라우저에서 돌린, 그리고 기기에서 작은 프로그램으로 돌린 같은 모델이, NVIDIA
> 그래픽 카드에서도 돌 수 있습니다 — 카드의 내장 드라이버만 빌리고 자기 수학은 직접 가져와서요. 빠르려고
> 숫자를 카드에 두고, 반복되는 루틴을 녹화해 더 빠르게 하고, 산술을 조심스럽게 하고, CPU에서 GPU 작업을
> 흉내 내길 거부하고 — 큰 버전에서는 — 카드 위에서 모델을 학습하고 줄이기까지, 언제나 조심스러운
> 전부-아니면-전무 방식으로.

🔧

```
 graph.json + 가중치
          │
          ▼
 VxRuntime → VxModel → vx_model_compile("cuda") → VxCompiledModel
                                                       │
                                                       ▼
                                      VxExecutionContext → VxResult
                                                       │
                ┌──────────────────── CUDA 제공자 ─────┴────────────────────┐
                │ dlopen libcuda · 임베드된 PTX JIT · 비공개 슬롯 테이블    │
                │ F32/W8A8 커널 · 선택적 CUDA 그래프 리플레이               │
                │ 풀 전용: 역방향 계획 · 옵티마이저 · W8 저작               │
                └────────────────────────────────────────────────────────────┘
                  기본은 엄격 FP32 · cuBLAS/cuDNN/cudart 없음 · TF32/텐서 코어 없음
```

🔬 **핵심 정리:**

- **"Driver API + 자기 PTX" 가 정체성 전부.** 빌린 의존성 하나(안정적 Driver API), 나머지는 전부 소유하고
  감사 가능 — cuBLAS/cuDNN/cudart/NCCL 없음, 실행 시점에 해석하니 하나의 바이너리가 "큰 GPU"와 "GPU 없음"을
  아우름.
- **레지던시가 핵심 추상화.** 런타임 소유 저장소가 내부 디바이스 슬롯에 매핑되고, 가중치는 카드에
  머뭅니다. 주소 재사용 위험은 격리와 에포크로 처리합니다.
- **정직함이 설계되어 있습니다.** 컴파일 시점 경로 증명, 걸리는 학습 실패, 트랜잭션 누적과 W8 저작,
  커널을 붙들지 않는 리플레이는 모두 같은 규칙을 표현합니다: 선택한 CUDA 정책을 만족하거나 실패를
  보고합니다.
- **공개 네이티브 생명주기를 따릅니다.** 모델 컴파일 때 백엔드 경로를 정하고 실행 컨텍스트가 이를
  재사용합니다. 결과 스냅샷은 컨텍스트 재사용과 독립적으로 읽을 수 있습니다.
