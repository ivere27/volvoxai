> 걸쳐서. 그 "내리막으로 작은 한 걸음" 도구가 **최적화기(optimizer)** 입니다. 그것을 계속 반복하는
> 것이 **학습 루프** 입니다. **LoRA** 라는 영리한 지름길도 만납니다: 기계 전체를 다시 쓰는 대신,
> 작은 "포스트잇" 몇 장을 붙이고 그것만 학습해 — 거대한 모델에 새 재주를 저렴하게 가르칩니다.

🔧 4장은 모든 가중치에 **기울기** 를 남겼습니다: 손실을 늘릴 방향. 손실을 *줄이려면* 각 가중치를 그
반대로 조금 딛습니다. 그걸 한 번 하는 게 **최적화기** 이고, 데이터에 걸쳐 반복하는 게 **학습 루프**
입니다. full 프로필의 `Trainer` 가 기울기, 최적화기 슬롯, 누적 구간, 그리고 비공개 작업
리비전을 소유합니다.

## 5.1 가장 단순한 최적화기: SGD

> 🌱 **아이디어.** 가장 단순한 규칙: 쪽지가 "내리막은 저쪽" 이라 하니, 그쪽으로 작은 한 걸음. 작은
> 걸음 = 느리지만 안전. 큰 걸음 = 빠르지만 계곡을 지나쳐 반대편으로 굴러떨어질 수 있음. 얼마나 큰
> 걸음을 딛는지를 **학습률(learning rate)** 이라 하며, 학습 전체에서 가장 중요한 다이얼입니다.
>
> *한 걸음, 손으로.* 가중치가 `0.5`, 그 쪽지(기울기)가 `+2.0`("오르막은 이쪽"), 학습률 `0.1`. 새
> 가중치 `= 0.5 − 0.1·2.0 = 0.3` — 내리막으로 작은 nudge. 다음 배치가 새 쪽지를 주고 또 nudge. 한 줄
> 산술씩, 그게 루프 전부입니다.

🔧 `grad` 가 오르막을 가리키면, 내리막으로 걷습니다 — 기울기 반대로 작은 한 걸음. 그것이 **확률적
경사 하강(Stochastic Gradient Descent)** 이며, 갱신은 한 줄입니다:

```c
// 모든 가중치 원소 i에 대해:
weights[i] -= learning_rate * (gradient[i] + weight_decay * weights[i]);
```

- **`learning_rate`** — 한 걸음 크기. 너무 작으면 학습이 기고, 너무 크면 지나쳐 손실이 발산합니다
  (가장 중요한 손잡이).
- **`weight_decay`** — 큰 가중치를 억제하는, 0을 향한 부드러운 당김(정규화).

> 🔬 **뜯어보기: "확률적" 과 "감쇠" 의 진짜 뜻.** *확률적(Stochastic)* 은 SGD의 **S** 입니다: 기울기가
> 전체 데이터셋이 아니라 **무작위 미니배치** 에서 오므로, 매 스텝은 진짜 내리막 방향의 *잡음 섞인
> 추정* 을 따릅니다 — 스텝당 더 싸고, 그 잡음이 나쁜 지점에서 흔들어 빠져나오는 데도 도움이 됩니다.
> `weight_decay · weights[i]` 는 **L2 정규화** 입니다: 0을 향한 일정한 당김으로, 단일 가중치가 거대해져
> 학습셋을 외우는 걸 막습니다.

```
   loss                    각 스텝: w ← w − lr · slope
    \                         큰 lr  ──►  ● ─────► ● 지나침 ✗
     \___                     작은 lr ─►  ●─►●─►●  안정 ✓
         \__●__●__●___
                       w*     (굴러가는 최소점)
```

SGD는 동작하지만, 모든 가중치·모든 방향에 같은 무딘 걸음 크기를 씁니다. 실제 학습은 대개 더 똑똑한
것을 씁니다.

## 5.2 일꾼: AdamW

> 🌱 **아이디어.** 순수 SGD는 모든 손잡이에 같은 크기 걸음을 딛습니다. **AdamW** 는 더 똑똑합니다:
> 각 손잡이에 *자기만의* 걸음 크기와 약간의 **관성(momentum)** 을 줍니다 — 내리막을 구르는 공이
> 방향을 유지하고 작은 요철에 흔들리지 않듯이. 쪽지가 계속 오락가락하는 손잡이는 작고 신중한 걸음을,
> 방향이 일정한 손잡이는 더 빨리 구릅니다. 실제 학습의 기본 선택입니다. 대가: 손잡이마다 여분의 숫자
> 둘을 기억해야 해서, 학습은 그냥 실행보다 메모리를 더 씁니다.

🔧 **AdamW** 는 각 가중치에, 그 가중치의 기울기 이력의 두 이동 평균(**모멘트, moment**)을 기억해
*자기만의* 적응적 걸음 크기를 줍니다. `Trainer.trainStep()` 에서 `updateMode: "adamw"` 와 최적화기
옵션으로 선택합니다.

- **`first_moment`**(`beta1`, ~0.9로 감쇠) — 평활화된 *평균* 기울기: 관성. 일정한 방향을 유지하고
  잡음 섞인 단일 배치 기울기를 견딥니다.
- **`second_moment`**(`beta2`, ~0.999로 감쇠) — 기울기 *제곱* 의 평활화된 평균: 전형적 *크기*. 걸음을
  그 제곱근으로 나누면, 크고 들쭉날쭉한 기울기의 가중치는 작고 신중한 걸음을, 작은 기울기의 가중치는
  상대적으로 큰 걸음을 딛습니다.
- **`step`** — 갱신 횟수. 두 모멘트가 예열되는 동안 편향 보정에 씁니다.
- **`weight_decay`** — AdamW의 "W": 기울기에 접지 않고 가중치에 직접 적용하는 분리된 감쇠(순수 Adam보다
  잘 동작하게 하는 디테일).

> 🔬 **뜯어보기: AdamW 갱신, 다섯 줄로.** 가중치마다, 스텝 `t` 의 기울기 `g` 로: `m = β1·m + (1−β1)·g`
> (관성), `v = β2·v + (1−β2)·g²`(전형적 크기); 그다음 차가운 시작을 **편향 보정** `m̂ = m/(1−β1ᵗ)`,
> `v̂ = v/(1−β2ᵗ)`; 스텝 `w −= lr · m̂ / (√v̂ + ε)`; 마지막으로 **분리된** 감쇠
> `w −= lr · weight_decay · w`. 편향 보정은 초반 몇 스텝에서만 중요하고(모멘트가 0에서 시작해 너무 작게
> 읽히니까), 분리 — `weight_decay·g` 를 기울기에 접는 대신 `w` 를 직접 감쇠 — 가 순수 Adam과의 유일한
> 차이이며 AdamW가 더 잘 일반화하는 이유입니다.

🔬 대가는 메모리입니다: Adam은 학습 가능한 가중치마다 **전체 크기 버퍼 두 개** 를 더 둡니다. 그래서
최적화기 상태 파일이 모델의 ~2배이고, 학습에 메모리 계획(9장)이 중요합니다.
`first_moment`/`second_moment` 버퍼가 바로 **체크포인트** 가 깨끗이 재개하려면 저장해야 하는
것입니다(§5.7).

🔬 VolvoxAI는 갱신마다 `updateMode: "sgd"` 또는 `updateMode: "adamw"` 로 규칙을 고릅니다.
최적화기 상태와 비공개 작업 리비전은 해당 `Trainer` 에 속하며, 추론 컨텍스트에는 속하지 않습니다.

## 5.3 하나의 학습 스텝, 처음부터 끝까지

> 🌱 **아이디어.** 한 "스텝" 은 지금까지의 모든 걸 엮습니다: 기계 실행, 틀림 재기, 책임 거꾸로 넘기기,
> 손잡이 밀기. 버튼 하나가 넷을 다 합니다. 어떤 손잡이가 움직여도 되는지도 정할 수 있어 — 뒤의
> 포스트잇 트릭에 편리합니다.

🔧 하나의 스텝이 4–5장의 모든 걸 엮습니다: 순전파 → 손실 → 역전파 → 갱신.

```javascript
const trainer = await VolvoxAI.createTrainer(model, {
  backend: 'cpu',
});

const step = await trainer.trainStep({
  inputs,
  logitsTensor: 'logits',
  targets,
  ignoreIndex: -1,
  trainableTensors,
  updateMode: 'adamw',
  optimizer: {
    learningRate,
    weightDecay,
    maxGradNorm,
  },
});

// 추론용으로 컴파일하기 전에 비공개 작업 리비전을 게시합니다.
await trainer.commit();
```

주목할 두 설계 선택:

- **`trainableTensors` 는 명시적 허용 목록입니다.** 이름 붙인 텐서만 기울기와 갱신을 받고, 나머지는
  전부 동결됩니다. 이것이 바로 LoRA와 어댑터 미세조정이 쓰는 메커니즘(§5.8) — 베이스 모델을 동결하고
  어댑터만 나열.
- **손실 타깃은 그래프가 아니라 호출에 있습니다.** 추론에 쓰는 *같은* 순방향 그래프를 학습에
  재사용하고, 교차 엔트로피 손실을 학습 때 그 `logits` 출력에 붙입니다. 별도의 "학습 모델" 은
  없습니다.

`trainStep()` 은 Trainer의 비공개 작업 리비전만 바꿉니다. 암묵적 게시는 없습니다.
`commit()` 이 이를 원자적으로 게시하고, `rollback()` 은 게시하지 않은 작업을 버린 뒤 마지막으로
커밋된 기준 상태를 복원합니다.

## 5.4 안정 유지: 기울기 클리핑

> 🌱 **아이디어.** 가끔 이상한 예제가 모든 걸 망칠 만한 거대한 "손잡이를 세게 돌려라" 쪽지를 냅니다.
> **기울기 클리핑** 은 안전벨트입니다: 걸음이 너무 커지려 하면 안전한 크기로 줄입니다. 긴 학습을
> 폭주에서 지키는 저렴한 보험입니다.

🔧 하나의 나쁜 배치가 가중치를 날려버릴 거대한 기울기를 낼 수 있습니다. **기울기 클리핑** 은 스텝
전에 전체 기울기 크기를 제한합니다: 전역 기울기 노름이 `max_grad_norm` 을 넘으면, 모든 기울기를 맞게
축소합니다. `Trainer` 의 NaN/Inf 거부와 함께, 이것이 긴 학습을 발산에서 막습니다. 최적화기 옵션에
`maxGradNorm` 을 지정하면 적용됩니다.

> 🔬 **뜯어보기: 하나의 *전역* 노름.** 클리핑은 **모든** 기울기에 걸친 노름을 한 번에 잽니다 — 모델의
> 모든 가중치에 대해 `total = √(Σ g²)` — 그리고 `total > max_grad_norm` 이면 *모든* 기울기에
> `max_grad_norm / total` 을 곱합니다. 전부를 같은 배율로 줄이면 결합된 스텝의 **방향** 은 그대로 두고
> 길이만 짧아집니다. ([9C장 §9C.11](09c-cuda-backend.md)의 CUDA 트레이너가 바로 이 하나의 전역 노름을
> 디바이스에서 계산합니다.)

## 5.5 배치와 기울기 누적

> 🌱 **아이디어.** *한* 예제로 판단하는 건 들쭉날쭉해 믿기 어려워, 걸음 전에 **배치(batch)** 의 예제들에
> 걸쳐 쪽지를 평균 냅니다 — 더 안정된 방향. 하지만 큰 배치는 많은 메모리가 필요합니다. 원하는 배치가
> 안 들어가면, **기울기 누적** 이 그것을 흉내 냅니다: 작은 그룹 몇 개를 처리하고, 그 쪽지들을 더한
> 뒤, *그다음* 한 걸음. 같은 효과, 적은 메모리.

🔧 한 번에 한 예제씩 갱신하지 않습니다 — 기울기가 너무 잡음이 많습니다. **배치** 의 예제들에 걸쳐
기울기를 평균 내고 한 번 딛습니다. 큰 배치는 더 매끄럽고 믿을 만한 방향을 주지만, 모든 예제의
활성화를 한꺼번에 메모리에 담습니다.

원하는 배치가 메모리에 안 들어가면, **기울기 누적** 이 흉내 냅니다: 작은(크기 1이라도) 배치 여럿을
돌려, 그 기울기를 같은 버퍼에 **더하고**, *그다음에야* 한 번의 최적화기 스텝. 이 누적 구간은
`Trainer.trainStep()` 이 소유합니다:

```
   accumulation_steps = 24, batch_size = 1   → 유효 배치 24
   ┌────────── 한 번의 최적화기 갱신 ──────────┐
   micro 1  micro 2  …  micro 24   flush → AdamW 스텝
   (grads += )        (grads += )   (모멘트 갱신, grads 0으로)
```

🔬 예를 들어 배치 크기 1과 누적 스텝 24를 쓰면 모든 활성화의 24개 복사본을 유지하지 않고 유효 배치
24를 만들 수 있습니다. 4장 §4.4의 역전파 `+=` 누적이 같은 기계이며, 여기서는 마이크로배치 *간* 에
재사용됩니다.

> 🔬 **뜯어보기: 나누는 걸 잊지 말 것.** 24개 마이크로배치를 누적하면 기울기 24개를 *더하지만*, 유효
> 배치 24는 그 **평균** 을 원합니다 — 그래서 트레이너는 더하기 전에 각 기여를 `1/accumulation_steps` 로
> (또는 손실을 `1/N` 로) 스케일합니다. 이걸 빼먹으면 실제 학습률이 몰래 24배 커집니다. 최적화기는
> **윈도당 한 번** 발화하므로 `step` — 그리고 그와 함께 LR 스케줄과 Adam의 편향 보정 — 은 마이크로배치가
> 아니라 *갱신* 마다 나아갑니다.

## 5.6 두 모드: 학습 대 평가

> 🌱 **아이디어.** 모델은 *공부* 할 때와 *시험* 볼 때 조금 다르게 행동합니다. 공부 중엔 일부러 살짝
> 자신을 불리하게 합니다(**dropout**) — 어느 한 요령에 기대지 못하게 해 정말로 배우도록. 시험 땐 그
> 불리함이 꺼집니다. 그리고 언제나 *공부하지 않은* 문제로 시험합니다 — 안 그러면 그냥 답을 외울 수
> 있으니까요. 이걸 헷갈리는 게 초보자의 전형적 실수입니다.

🔧 어떤 연산은 학습 중 다르게 행동합니다:

- **Dropout** 은 *학습 중* 활성화의 일부를 무작위로 0으로 만들고(추론 땐 **꺼짐**), 모델이 단일
  유닛에 과의존하지 못하게 합니다. VolvoxAI는 결정론적 *역스케일* dropout을 사용해 — 학습 중
  생존자를 키워, 평가 때 보정이 필요 없습니다.

> 🔬 **뜯어보기: 역스케일, 그리고 결정론적.** 드롭 확률 `p` 로, dropout은 각 활성화를 확률 `p` 로 0으로
> 만들고 생존자를 `1/(1−p)` 로 곱합니다 — 그래서 *평균* 신호가 그대로라 추론은 재스케일 없는 순수
> 항등이 됩니다. VolvoxAI의 커널은 또 **결정론적** 입니다: 마스크를 전역 RNG 상태가 아니라
> `(seed, counter)` 쌍에서 유도하므로, 같은 스텝이 모든 백엔드에서 같은 마스크를 재현하고 그 역방향 쌍이
> 정확히 재생성할 수 있습니다(9C장의 CUDA dropout에서 본 `seed`/`counter`/`threshold` 파라미터).
- **정규화** 도 마찬가지로 학습/평가 구분을 존중해야 합니다.

그래서 학습은 **두 모드** 를 번갈아 합니다: *학습* 모드(dropout 켜짐, 가중치 갱신)로 학습 데이터를,
*평가* 모드(dropout 꺼짐, 갱신 없음)로 떼어둔 검증 데이터를 돌려 실제 진전을 잽니다. 이걸 섞으면 —
dropout 켠 채 평가하거나 검증셋으로 갱신 — 전형적 버그입니다.

## 5.7 루프

> 🌱 **아이디어.** 이제 전부를 루프로 감쌉니다: 공부 자료를 여러 번 훑고(한 번의 전체 통과가
> **에폭**), 작은 걸음을 딛으며, 이따금 떼어둔 문제로 시험해 *정말* 나아지는지 봅니다. 그리고
> **진전을 저장** 해, 충돌이 며칠 치 연습을 날리지 않게 합니다. 끝에 다가갈수록 걸음 크기를 줄여,
> 모델이 답 위에서 튀지 않고 부드럽게 안착하게 합니다.

🔧 애플리케이션이 소유하는 완전한 실행은 이렇게 생겼습니다:

```
각 에폭마다:
    학습 데이터의 각 배치마다:                # 학습 모드
        loss = trainer.trainStep(...)         # 순전파→손실→역전파→AdamW
        learning_rate = cosine_schedule(step) # 실행 동안 LR을 서서히 낮춤
    trainer.commit()                          # 이 비공개 리비전을 게시
    검증 데이터의 각 배치마다:                # 평가 모드, 갱신 없음
        정확 일치 정확도 측정
    검증이 개선되면:  "best.checkpoint" 저장
    항상:            "last.checkpoint" 저장
```

🔬 장난감이 아니라 *진짜* 루프로 만드는 디테일:

- **학습률 스케줄.** LR은 상수가 아닙니다 — **코사인 스케줄** 이 예열 후 0을 향해 부드럽게 낮춰,
  더 빨리 학습하고 더 부드럽게 착지합니다. VolvoxAI에서 이는 *호출자 정책* 입니다(예제가 계산해 매
  스텝 새 `learning_rate` 를 넘김). 엔진은 적용만 합니다.
- **평가 지표.** 손실이 최적화기를 이끌지만, 애플리케이션은 정확 일치 정확도나 라우팅 점수처럼
  사용자에게 중요한 과제 지표를 별도로 계산합니다.
- **체크포인트.** `await trainer.exportCheckpoint()` 는 비공개 작업 리비전의 가중치, AdamW 모멘트,
  파라미터별 스텝, 학습 스텝, 애플리케이션 메타데이터를 저장합니다.
  `importModelCheckpoint(checkpoint).graph` 로 Model을 만든 뒤 `checkpoint` 를
  `VolvoxAI.createTrainer(model, options)` 에 넘겨 재개합니다. 굴러가는 `last` 와 지금까지의 최선
  `best` 정책은 애플리케이션이 소유합니다.

> 🔬 **뜯어보기: 코사인 곡선, 그리고 왜 "best" ≠ "last".** 코사인 스케줄은 짧은 **예열** 동안 LR을 올린
> 뒤 `lr = ½·lr_max·(1 + cos(π · t / T))` 를 따라 지평선 `T` 까지 ~0으로 내립니다 — 초반엔 큰 걸음으로
> 탐색, 후반엔 작은 걸음으로 최소점에 안착. `best`(최고 검증 점수)와 `last`(최신)를 둘 다 저장하는
> 이유는 학습이 결국 **과적합** 하기 때문입니다: 어느 지점을 지나면 학습 손실은 계속 내려가는데 검증
> 손실은 다시 *올라갑니다*. `best` 는 조기 종료 보험이고, `last` 는 `--resume` 이 이어가는 지점입니다.

## 5.8 LoRA: 베이스 모델을 건드리지 않는 미세조정

> 🌱 **아이디어.** 거대한 모델을 통째로 다시 학습하는 건 느리고 새 거대 복사본을 만듭니다. **LoRA**
> 는 포스트잇 트릭입니다: 원래 기계는 있는 그대로 *동결* 해 두고, 각 큰 부분 옆에 조절 가능한 작은
> 쪽지 몇 장을 붙입니다. 쪽지만 학습합니다. 결과는 공유하기 좋은 작은 파일이고, 한 베이스 기계가 서로
> 다른 "포스트잇 묶음" 을 갈아 끼워 다른 일을 할 수 있습니다. 이것이 한 모델을 여덟 새 과제에, 여덟
> 개의 통째 복사 없이 가르치는 방법입니다.

🔧 전체 학습은 모든 가중치를 갱신합니다 — 비싸고, 통째로 새 수 기가바이트 모델을 만듭니다. **LoRA**
(저랭크 적응)는 현대적 지름길입니다: **사전학습 가중치를 동결** 하고, 각 큰 Linear 옆에 작은 저랭크
행렬 쌍(선택한 rank)을 끼워 넣습니다. 그 어댑터만 학습합니다.

```
   동결 베이스:  y = x · W          (W는 사전학습 그대로 유지)
   + LoRA:       y = x · W  +  (x · A) · B      A:[in,8]  B:[8,out]   ← A,B만 학습
```

🔬 rank 8은 전체 가중치 행렬 옆에서 미미해서, 학습 가능한 집합이 자릿수 단위로 줄어듭니다 — 바로
`trainableTensors` 허용 목록(§5.3)이 표현하는 것입니다. `ModelBuilder.loraLinear()` 는
명시적인 A/B Graph 가중치와 그 이름을 만들고, 일반 `Trainer.trainStep()` 이 그 이름만 갱신합니다.
배포 정책은 다음 아티팩트를 내보낼 수 있습니다:

- **`lora.safetensors`** — 학습된 델타만, 작고 공유 가능.
- **`lora_base/`** — 손대지 않은 베이스 패키지(인라인 LoRA 텐서 0).
- 베이스를 로드하고 어댑터(`volvox.adapter.v1`)를 활성화하면 미세조정된 모델을 되찾습니다. 예제는
  병합-인라인 경로와 베이스+어댑터 경로가 동일한 로짓을 내는지 *검증* 한 뒤에야 그 쌍을 신뢰합니다.

이래서 종합 장(10장)이 하나의 공유 멀티모달 모델을 여덟 개의 통째 복사 없이 여덟 영수증 과제에 맞출
수 있습니다 — 동결된 백본 하나 위의 작은 어댑터 여덟 개.

> 🔬 **뜯어보기: 왜 LoRA는 무연산으로 시작해 값싸게 유지되나.** 어댑터는 `ΔW = (α/r)·A·B` 이고 `A` 는
> 무작위, `B` 는 **0** 으로 초기화되어, 첫 스텝에 `ΔW = 0` — 미세조정이 사전학습 모델과 *정확히* 똑같이
> 시작해 `B` 가 배우면서만 벗어납니다; `α/r` 인자가 랭크 `r` 을 바꿔도 갱신 크기를 온전하게 유지합니다.
> 파라미터 산술이 핵심입니다: `[in, out]` 행렬은 `in·out` 개 가중치지만 rank-8 어댑터는 `8·(in + out)`
> 개뿐 — `1024×1024` 층이면 ~100만 대 ~1.6만, ~60배 축소. 추론 때 `W + ΔW` 를 하나로 **병합** 할 수
> 있어, 병합된 LoRA 모델은 실행에 추가 비용이 없습니다.

## 5.9 방금 배운 것

> 🌱 **아이디어 정리.** 학습 = 손잡이를 내리막으로 조금 돌리기(**최적화기**)를, 많은 예제에 걸쳐
> 반복(**루프**)하되, 안전벨트(클리핑), 더 안정된 평균(배치), 정직한 시험(학습 대 평가), 저장된
> 진전(체크포인트)과 함께. 그리고 기존 모델에 새 재주만 저렴하게 가르치고 싶으면, 통째로 재건하는
> 대신 **LoRA** 포스트잇을 씁니다.

🔧

- **최적화기** 는 각 가중치의 기울기를 실제 걸음으로 바꿉니다. **SGD** 는 `w -= lr·grad`, **AdamW** 는
  두 개의 기울기 **모멘트** 로 모든 가중치에 적응적 걸음을 줍니다(가중치당 여분 버퍼 둘의 대가 —
  학습 체크포인트의 대부분).
- 하나의 **학습 스텝** 은 순전파 → 손실 → 역전파 → 갱신이며, `Trainer.trainStep()` 으로 노출되고,
  무엇이 변할지 정하는 명시적 **`trainableTensors`** 허용 목록을 씁니다.
- **루프** 는 실전에서 통하게 하는 부분을 더합니다: **배치** 와 **기울기 누적**(물리 배치 1에서 유효
  배치 24), 안정성을 위한 **기울기 클리핑**, **학습 대 평가 모드**(dropout 켜짐/꺼짐), **코사인 LR
  스케줄**, **과제 지표**, 그리고 실행을 정확히 재개하도록 최적화기 상태를 저장하는 **체크포인트**.
- **LoRA** 는 베이스를 동결하고 작은 rank-8 어댑터를 학습해 미세조정합니다 — 같은 허용 목록 메커니즘,
  일부의 비용, 그리고 공유 가능한 `lora.safetensors`.

이제 좋은 가중치를 *찾을* 수 있습니다. 3부는 다음 질문을 던집니다: 모델을 학습한 뒤, 어떻게 배포할
만큼 작고 빠르게 만들까? 그것은 숫자가 저장되는 방식에서 시작합니다.
